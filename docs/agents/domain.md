# Domain docs

This repository uses a single domain context.

Before architecture, diagnosis or implementation work:

- Read `CONTEXT.md` at the repository root.
- Read relevant architectural decisions under `docs/adr/`.
- Use the glossary’s exact domain terms in PRDs, issues, tests and implementation names.
- Surface conflicts with an existing ADR explicitly instead of silently overriding it.

If a needed concept is absent, add it to `CONTEXT.md` only after its meaning is established by the product behavior or an explicit decision.
